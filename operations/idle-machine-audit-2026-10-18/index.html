    Changes and verification

    No Python producer activity-only false red was found, so this PR changes no runtime health policy. Six regression cases cover a 49h-old corpus, repeated idle health ticks with an empty successful search, actual backup/job failures retained in the badge, and verified no-op attempts without an upload or with >30d history. The six tests pass on the baseline behavior. The first fixture run exposed a WAL-copy setup mistake, corrected by staging committed DELETE-journal bytes; it was not a production defect. Follow-up: #1396.

    Local targeted pytest: 477 passed. Ruff checks pass. CI and native visual verification remain separate review/deploy gates. No production data changed.

    Surface sweep: Entry points — health CLI, observability job, watchdogs and doctor reviewed; Clients — Dashboard, Jobs, Backups and menu consumers reviewed; Providers — local Python/Swift, both installed Macs sampled; Contracts — JSON health/badge/observability shapes unchanged; Reverse states — empty, no-op, failed backup and failed job covered; Connection modes — local MBP and SSH M1 read-only, supervisor status only; Docs — health guide's obsolete empty-canary failure claims corrected.
